## 검증 기록

- 기준 감사: 타입·빌드 통과, 단위 396개 통과. 전체 E2E는 47/50이며 초기 로드 실패 2건과 준비 완료 대기 부족 1건을 별도 기록했습니다.
- 로딩 완료 대기 후 5,000개 붙여넣기와 Undo 비교는 통과했습니다. 향후 테스트에서 이미지 파일명만으로 준비 완료를 판단하지 않습니다.
- 실제 ONNX S640/S1024 GPU, N1024 CPU 및 프리셋·3장 일괄 실행은 기준 감사에서 확인했습니다. 실제 M/L·2048 전체 모델, 산업 정답 정확도, 모든 포맷 왕복은 별도 확인 범위입니다.

### 1단계 적용 후

- 타입 검사·빌드 통과, 단위 **66개 파일·398개** 통과. 새 회귀는 Fabric 확대 API와 ROI가 라벨 내보내기에 섞이지 않는지 확인합니다.
- 관련 E2E **20개 통과**: 확대/ROI, 720p 고정 작업·미저장 상태·중단/재실행, 여러 이미지 예시·프리셋·배치, 브러시/지우개·팬/줌·1024/2048 좌표, 좁은 화면·다크 테마. 최신 빌드 전체 E2E는 **51/53개 통과**(11.4분). 최초 정렬/이력 2건은 페이지 `load` 대기 시간 초과였습니다. `DOMContentLoaded`와 앱 API 준비 완료 대기로 보완 후 **2/2개 재검증 통과**(16.2초). 기능 시나리오 53개를 확인했으며, 한 번의 전체 실행에서 53개가 모두 통과한 것으로 기록하지 않습니다. 초기 로드 지연의 정확한 원인은 확정하지 않았습니다.
- 실제 브라우저 ONNX **S640 · GPU/WebGPU**: 기존 박스 1개를 예시로 가져와 `sample_1.jpg`에서 미리보기 박스 2개 확인. 팝업 하단의 준비 상태/결과와 원본 207개 보존 확인. 이 수치는 정확도 평가가 아닙니다. CPU 진행/실패 경로는 서비스 응답을 제어한 E2E로 확인하며 이번 단계에 새 Windows 설치 파일을 만들지 않았습니다.
- Detection에서 실제 **CFSR x2 · GPU/WebGPU**도 확인했습니다. ROI 108×90을 216×180으로 처리한 뒤 원본 좌표·207개 라벨이 유지됐고 실행 오류는 없었습니다.
- 최초 관련 실행은 닫기 버튼 선택자 중복 및 전역 진행 패널이 팝업 Stop을 가리는 문제로 실패했습니다. 선택자를 ID로 지정하고, 팝업 내 진행 UI가 있을 때 전역 패널을 숨긴 뒤 관련 20개를 재검증했습니다. 최초 실패 로그도 보존합니다.
- 재빌드 후 기존 Vite가 디스크의 최신 코드 대신 이전 `dist` 모듈을 제공하는 것을 HTTP 응답과 파일 비교로 확인했습니다. 해당 전체 실행을 중단하고 새 서버에서 최신 코드 제공을 확인한 후 전체 검증을 재시작했습니다. 캐시된 실행은 최종 판정에 사용하지 않습니다. 팝업 재열기 후 로딩 표시가 남지 않도록 성공 시 Ready를 표시하고 새 E2E로 확인했습니다.
