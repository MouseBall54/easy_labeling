# 라벨 박스 즉시 표시 개선안

2026-10-07 · 기준 소스 `8f1c063` 대비 **현재 이미지 우선 로딩 구현 · 검증 완료**.

## 결론

현재 이미지의 TXT 읽기와 캔버스 적용을 폴더 전체의 상태/Review 검사로부터 분리했습니다. Detection 폴더 등록 시 전체 TXT를 미리 매칭하거나 읽지 않습니다. 선택한 이미지의 라벨을 새로 읽고, 기존 함수로 현재 이미지의 판정을 확인한 뒤 전체 박스를 한 번에 교체합니다. 다른 이미지의 TXT는 해당 이미지를 열거나 전체 Review/필터/새로고침을 요청할 때 읽습니다. 전체 검사를 자동으로 시작하는 백그라운드 작업이나 라벨 내용 캐시는 추가하지 않았습니다.

## 실제 병목 측정

기준 커밋의 [`activateLabelFolder`](../src/bootstrap/file-system-adapter.ts) 경로는 전체 이미지 상태 갱신 → Review 상태 → 전체 Review → 클래스 → 현재 라벨 → 캔버스 순서였습니다. [`refreshImageWorkflowStatus`](../src/features/images/image-session-service.ts)는 전체 TXT를 읽고 개수를 파싱하며, 전체 Review가 같은 TXT를 다시 읽었습니다. 따라서 현재 이미지를 화면에 띄우기 전의 대기가 다른 이미지 수에 비례했습니다. 아래 표는 구현 전 원인 계측입니다.

실제 Windows Electron/production preload/file://에서 샘플 이미지당 5,000개·5클래스와 두 라벨 폴더를 사용했습니다. 이미지 6장은 전환 4회, 60장은 전환 2회의 평균입니다. 임시 계측은 함수 시작/종료를 기록했으며 소스 변경 없이 컴파일 산출물에서만 적용한 뒤 최종 빌드로 제거했습니다.

|---|---:|---:|
| 현재 라벨 로딩 함수 | 1.8ms | 2.1ms |
| 폴더 전체 Review | 290.9ms | 2,964.4ms |
| 현재 이미지의 5,000개 Rect 생성/초기 글자 배치 | 84.5ms | 87.8ms |

## 승인된 설계

1. **현재 이미지 우선 로딩**. 이미지 목록은 기존대로 열거하되 전체 라벨 내용/개수를 먼저 읽지 않습니다. 전환 전 저장과 폴더 접근 확인, 해당 폴더의 클래스/Review 설정 로딩을 유지합니다. 현재 이미지의 Detection/Segmentation 라벨 로딩 경로를 유지해 현재 이미지의 기존 오류 처리를 보존합니다. 현재 이미지의 Review를 계산하고 모든 Rect를 준비한 뒤 한 번에 적용합니다. 다른 이미지와의 사전 대응표나 라벨 결과 캐시는 만들지 않습니다.
2. **전체 검사는 사용 시 수행**. 전체 Review 큐, 라벨 개수/이슈 필터, 명시적 새로고침처럼 전체 결과가 필요한 요청에서 나머지 파일을 검사합니다. 기존 worker 요청/취소 패턴을 활용해 UI 스레드의 긴 정지를 줄입니다. 미검사 항목은 `검사 대기`로 표시하고 검사 완료 전의 전체 개수/필터 결과를 확정값으로 표시하지 않습니다. 처음 열었을 때 백그라운드에서 모든 라벨을 자동으로 매칭하는 방식도 제외합니다.
3. **중복 화면 갱신 축소와 계산 후보 실험**. 캔버스는 기존 Fabric/YOLO 파서/히스토리를 유지하며 교체 중 렌더 예약과 중복 라벨 목록 갱신을 묶습니다. 중복 박스의 좌표별 후보 선별은 아래 독립 실험에서 밀집 중첩에 불리해 실제 프로그램에 적용하지 않습니다. 기존 검사 함수와 비교 순서를 그대로 유지합니다.

기존처럼 **폴더 전체 검사 완료 전까지 모든 작업을 막는 시점까지 동일하게 유지**해야 한다면, 첫 화면을 먼저 보여 주더라도 즉시 편집은 허용할 수 없습니다. 권장안은 현재 이미지의 검증/편집 준비를 먼저 확정하고 전체 결과는 요청 시 확정하는 방식입니다. 판정 기준과 최종 결과는 유지하지만 다른 이미지의 검사 완료 시점과 표시 상태는 달라집니다.

## 동일 판정 계산의 사전 실험

프로그램 소스에 적용하지 않은 독립 실험에서 클래스별 X좌표 정렬과 겹침 후보 선별을 시험했습니다. 기존 `inspectDetectionLabels`와 결과 객체 전체를 비교해 **1,002개 사례에서 일치**했습니다. 무작위 좌표/클래스, 동일 박스, 경계 밖, NaN/Infinity/음수 크기/잘못된 행, IoU 임계값 0·음수·0.01·0.5·0.9·1·NaN, 필수 클래스, 메시지와 인덱스 순서를 포함합니다.

| Node 독립 계산 실험, 5회 중앙값 | 기존 | 후보 |
|---|---:|---:|
| 5,000개 규칙 배열과 일부 중복 | 69.4ms | 3.7ms |
| 1,000개가 같은 위치에 겹친 배열 | 19.7ms | 23.8ms |

밀집 중첩에서는 후보를 줄일 수 없고 정렬 비용으로 더 느려졌습니다. 모든 데이터에서 빨라진다고 주장하지 않으며, 이 계산 변경은 즉시 표시 경로 분리보다 후순위입니다. 이 수치는 Node 계산 실험이며 Electron 화면 표시 성능이나 전체 앱 회귀 통과를 의미하지 않습니다. [실험 결과](../output/label-quality-experiment.json).

## 기존 동작을 유지할 기준

- 현재 TXT는 선택할 때 새로 읽어 외부 변경을 반영합니다. 저장 형식·클래스·좌표·박스 순서·원본 YOLO 문자열의 보존 계약을 유지합니다.
- 현재 이미지가 준비되기 전에는 편집/저장을 허용하지 않습니다. 실패 시 부분 박스나 새 폴더의 확정 상태를 남기지 않고 기존 화면/세션을 복원합니다.
- 전환 전 Save/Auto save, 팬/줌, 숨김 클래스, 클래스 색, 선택·다중 선택·붙여넣기·Layout·Undo, Segmentation 전환을 기존 기준으로 검사합니다.
- 비동기 검사는 폴더/이미지/설정/문서 변경을 식별해 이전 요청의 결과가 현재 상태를 덮어쓰지 못하게 합니다. 빠른 Ctrl+숫자 전환, 검사 중 Save/Auto save, 이미지 이동, 취소와 I/O 실패를 확인합니다.
- 전체 검사를 요청하면 기존 구현과 이미지별 finding·severity·개수·메시지·인덱스·순서가 일치해야 합니다. 미검사 상태를 검사 완료/정상으로 대신하지 않습니다.
- 기존 단위 413개 및 관련 E2E 14개와 추가 동등성 검사를 다시 통과하고, 같은 데이터로 최초 표시/전환/편집 준비/전체 검사 시간을 각각 비교합니다.

## 기대 효과와 한계

따뜻한 로컬 파일 조건에서 5,000개 현재 이미지 준비를 **200~300ms 수준으로 만드는 것**이 설계 목표였습니다. 구현 후 반복 전환 준비는 6장 평균 238.7ms, 60장 243.4ms로 측정했습니다. 최초 폴더 로딩에는 이미지 디코딩과 프로필/도구 준비도 포함돼 약 488.3/530.2ms가 필요했습니다. 다른 이미지가 늘어도 현재 이미지 표시를 전체 Review 시간만큼 늦추지 않는 것이 핵심 완료 기준입니다.

처음 사용하는 이미지의 디코딩, NAS/느린 디스크, 모두 겹친 박스, 많은 글자를 강제로 표시하는 설정은 별도로 측정합니다. 현행 5,000개 Fabric 생성만 약 85ms이므로 모든 조건에서 한 프레임(약 16ms) 내 표시를 보장하지 않습니다. WebGL 렌더러 교체, 모든 라벨의 사전 로딩, 오래 유지하는 파싱 결과 캐시, 편집 객체의 지연 생성은 이번 우선안에 넣지 않습니다.

## 구현과 같은 조건의 전후 비교

현재 이미지의 Detection/Segmentation 로딩 경로를 유지하고, 현재 이미지의 Detection finding을 기존 `inspectDetectionLabels`로 계산합니다. 준비한 Rect를 렌더 예약 없이 한 번에 교체하고, 빈 TXT로 전환하면 이전 박스를 비웁니다. 폴더 전환은 이미지/AI 캐시와 팬·줌을 유지합니다. 숨겨진 Review 이슈 목록의 DOM은 Review를 열 때 만들며, 준비 완료 뒤 화면을 650ms 더 막던 지연을 제거했습니다. 오류/제한 상태의 준비 안내는 유지합니다.

전체 Review는 요청 시에만 module worker에서 같은 검사 함수를 사용합니다. 미검사 항목은 시계 아이콘/`…`와 `Not checked · 검사수 / 전체수`로 표시합니다. 완료 전의 전체 큐 이동을 잠그고, 실패/취소 시 일부 finding을 전체 확정 결과로 게시하지 않습니다. 이미지·폴더 이동, Save/Auto save, 문서 편집, 모드/규칙 변경으로 이전 검사를 취소합니다. 규칙 저장 중 들어온 새 작업/편집도 식별해 늦게 전체 검사를 시작하지 않습니다. 현재 이미지의 I/O/마스크 오류는 이전 세션 복원을 유지합니다.

## 최종 검증

타입 검사·빌드와 단위 **67파일·424개**가 통과했습니다. 기존 관련 E2E **14/14**, 추가 현재 이미지 우선 로딩 E2E **2/2**도 통과했습니다. 실제 Windows Electron에서는 4,000/5,000개 로딩, 두 모드의 폴더 전환/저장, Save/Auto save의 박스 보존과 명시적 전체 경계 정리를 확인했습니다. 브라우저에서는 Layout 두 Apply/Undo/JSON 왕복(2·600·4,000·5,000개), 클래스 색, Review, 전체 샘플 17장의 두 모드, Automation을 확인했습니다.
