# Refine Reclass: 결함 박스 후보 찾기와 클래스 변경

## 의도

박스 위치를 다시 잡는 Refine과 달리, 이미 있는 박스 **안쪽 픽셀**이나 **Refine 결과 면적**으로 결함 박스를 찾아 다른 클래스로 바꾼다. 예: 가운데가 어두워야 하는 구조물에 밝은 얼룩이 섞이면 "덜 채워진"(이 데이터셋의 class 0 `unfilled`)으로 본다. 사용자는 전에 박스 가운데를 crop해 평균 픽셀값이 기준 이상이면 결함으로 판단한 적이 있다. 조건, 바꿀 클래스 번호와 이름은 데이터셋마다 다르다.

## 목표

- 이미지 한 장에서 규칙에 맞는 박스를 **후보로 표시**하고, 사용자가 확인한 뒤 클래스를 바꾼다(자동 변경 없음).
- 판정 세 가지, 모두 지원:
  1. **가운데 평균:** 가운데 crop의 평균 픽셀값 ≥ 기준값
  2. **밝은 픽셀 비율:** 가운데 crop에서 기준 밝기보다 밝은 픽셀 비율 ≥ 설정값
  3. **면적 감소:** Refine으로 다시 계산한 면적이 원래 대비 설정 비율 이상 감소
- 규칙마다 판정을 **AND / OR**로 묶는 방식을 고를 수 있다.
- **Refine Lab에서 설정값을 바꿔 가며 테스트**할 수 있다.
- 3072×2048 이미지에 박스 600~800개가 있어도 후보가 눈에 잘 띄어야 한다.
- 기존 Refine 검토 표시(노란 점선 + 굵은 변)를 같은 새 표시 체계(C안)로 바꾼다. 지금은 테두리가 굵어진 것처럼만 보여 시인성이 나쁘다.

## 비목표

- 폴더 전체 일괄 검사(지금은 이미지 한 장만).
- 박스 위치 이동. 면적 감소 판정은 Refine을 계산만 하고 박스는 그대로 둔다.
- 자동 클래스 변경.

## 실패로 보는 것 (반목표)

- 밀집 이미지에서 핀이나 태그가 이웃 박스를 덮어 이미지를 보기 어려워지는 것.
- 흐리게 처리나 표시가 저장 데이터(YOLO `.txt`)나 undo 기록에 섞이는 것.
- 옛 `refine-settings.json`이나 프리셋 파일을 못 읽게 되는 것.

## 사용자가 정한 것

- 후보로 표시한 뒤 사용자가 바꾼다.
- 표시는 **C안**: 후보와 검토 대상만 또렷하게 두고 나머지 박스는 흐리게, 모서리에 핀, 약한 변은 바깥 화살표, reclass 후보는 "→ 0 unfilled" 태그.
- 밀집(600~800개) 상황을 고려해 핀과 태그를 설계한다.
- 이미지 한 장 단위.
- 평균과 비율 둘 다 지원, AND/OR 둘 다 선택 가능.
- Refine Lab에서 테스트 가능.
- Refine 사이드 탭에서 Reclass를 Refine 옵션과 따로, 위쪽 별도 섹션으로 둔다.

## 설계 (사용자가 따로 정하지 않은 부분은 [판단] 표시)

### 규칙 모델

```
ReclassRule {
  enabled: boolean
  fromClasses: string[]        // 검사할 클래스 (빈 배열 = 전체) [판단]
  toClass: string              // 바꿀 클래스 id
  combine: "and" | "or"
  crop: number                 // 가운데 crop 비율, 0.1~1, 기본 0.5 [판단]
  mean:   { enabled, min }               // 0~255
  bright: { enabled, level, minRatio }   // level 0~255, minRatio 0~1
  shrink: { enabled, minRatio }          // 0~0.99, 면적 감소율
}
```

- 규칙 목록을 위에서부터 평가하고, 박스마다 처음 맞는 규칙이 후보를 만든다 [판단].
- 켜진 판정이 없는 규칙은 아무것도 만들지 않는다.
- 판정 픽셀은 Refine과 같은 이미지(`imageSource` Original/Processed, `processing` 스냅샷)를 쓴다 [판단]. Lab에서 본 픽셀과 판정이 일치하게 하려는 것이다.
- 밝기 판정은 Refine과 같은 8-bit gray(`toGray`) 기준이다.
- **면적 감소 기준(사용자 결정):** 이미지를 열 때 파일(`.txt`)에서 불러온 박스 크기와 비교한다. Find candidates는 지금 박스에 Refine을 계산만 해 보고(박스는 옮기지 않음), 그 결과 면적을 불러온 면적과 비교한다. 그래서 Refine all을 적용한 뒤에도 "처음보다 얼마나 줄었나"로 판정된다. 손으로 고친 박스도 같은 기준이다.
  - 불러온 크기는 이미지를 열 때 박스 id별로 메모리에 기록한다. 저장한 뒤에도 다른 이미지로 넘어가기 전까지는 처음 연 시점 값을 유지한다 [판단].
  - 새로 그린 박스는 불러온 크기가 없으므로 지금 박스 크기를 기준으로 쓴다 [판단].
  - Lab 케이스도 같은 기준을 쓴다(`area −31% vs loaded`).
- 면적 비율 계산 방식은 기존 `RefineResult.areaChange`와 같다(기준 면적만 다름). Refine 설정은 지금 Refine 실행과 같은 `runConfig()`(클래스 설정 또는 "Run with" 프리셋)를 쓴다 [판단].
- 규칙 목록은 항상 현재 설정 문서(`refine-settings.json`)에서 읽는다. "Run with" 프리셋은 면적 감소 판정에 쓰는 Refine 파라미터만 바꾼다 [판단].
- Refine이 꺼진 클래스(`enabled: false`)는 면적 감소 판정을 "맞지 않음"으로 친다. AND 규칙이면 그 박스는 후보가 되지 않고, OR 규칙이면 평균/비율만으로 판정한다. Lab에는 "refine off"로 표시한다 [판단].
- 순수 판정 함수는 `src/domain/refine/`(예: `reclass.ts`)에 DOM 없이 둔다. 입력은 gray 이미지(또는 crop), 박스, 규칙, 선택적 `areaChange`이고, 출력은 박스별 `{ match, ruleIndex, toClass, mean, brightRatio, areaChange }`이다. 수치는 Lab과 태그에 표시한다.

### 저장

- `refine-settings.json`에 `reclass: ReclassRule[]`를 추가한다. 없으면 빈 배열로 읽는다(옛 파일 호환). `parseRefineSettings`가 범위 밖 값은 잘라낸다.
- Refine 프리셋에 `reclass`를 함께 저장한다 [판단]. 데이터셋마다 다른 규칙을 프로필 프리셋(`Refine Presets`)으로 옮길 수 있게 하려는 것이다. 이 필드가 없는 옛 프리셋은 적용할 때 현재 규칙을 그대로 둔다(이미지 필드와 같은 방식).

### Refine 사이드 탭

Refine 옵션(Settings / Run with / Apply)과 분리된 **Reclass** 섹션을 위쪽에 둔다.

- 규칙 요약 한 줄(예: "1 rule: class 1 → 0 unfilled, mean ≥ 140 OR bright ≥ 20%"). 편집은 Lab에서 한다(Refine과 같은 원칙).
- **Find candidates** 버튼: 현재 이미지 전체를 판정해 후보를 캔버스에 표시한다.
- 개수 표시: "reclass 후보 12".
- **Reclass selected**, **Reclass all candidates**: 클래스 변경은 한 번의 undo 단계로 처리한다. 기존 class 변경 경로를 재사용한다.
- 후보 넘기기는 기존 Review 이동(N / Shift+N)에 합친다. 하나의 queue에 Refine 검토 대상과 reclass 후보를 위치 순서대로 넣고, F(Approve)는 바꾸지 않고 확인만 처리해 표시를 지운다 [판단].
- F로 확인한 후보는 그 이미지에 머무는 동안 기억해서 다시 Find해도 나오지 않는다. 박스의 위치나 클래스가 바뀌거나 다른 이미지로 넘어가면 잊는다. 디스크에는 저장하지 않는다 [판단].
- 한 박스가 Refine 검토 대상이면서 reclass 후보이면 queue에는 한 번만 들어간다. 핀 두 개를 나란히 그리고(마젠타 왼쪽, 노랑 오른쪽), F는 둘 다 지운다 [판단].
- 새 단축키는 추가하지 않는다 [판단]. 꼭 필요하면 `resolveRefineShortcut`, `event-manager-adapter.ts`의 기존 바인딩 확인과 충돌 테스트를 함께 추가한다.
- 박스를 손으로 바꾸면(클래스나 위치) 그 박스의 후보 표시를 지운다. Refine 검토의 hand-edit 규칙과 같다.

### Refine Lab 테스트

- 설정 편집기에 **Reclass** 섹션을 추가해 규칙 목록, 판정별 on/off와 값, AND/OR, from/to 클래스를 편집한다. Lab의 draft 원칙(Save 전까지 저장 안 함)을 따른다.
- 케이스(기존 "Selection / Classes / All" 소스, 최대 24개)마다 판정 결과를 보여 준다:
  - 맞으면 마젠타 핀과 바뀔 클래스 번호.
  - 수치 한 줄: `mean 142 · bright 23% · area −31%`. 기준을 넘은 값은 강조한다.
  - 줌 뷰에 가운데 crop 영역을 점선 사각형으로 그린다. 밝은 픽셀 판정이 켜져 있으면 기준 밝기 이상 픽셀을 옅은 마젠타로 덮어 보여 준다 [판단].
- 값을 바꾸면 바로 다시 판정한다(기존 Lab 실시간 재계산과 같은 흐름).
- 케이스 목록 요약에 "N of M match"를 표시한다. M은 규칙의 `fromClasses`에 속하는 케이스만 센다. 규칙이 검사하지 않는 클래스의 케이스에는 판정 표시를 하지 않는다 [판단].

### 캔버스 표시 (C안, Refine 검토 표시도 교체)

`#refineOverlayCanvas`에서 그린다. 핀은 화면 크기 기준으로 고정된다.

- **나머지 흐리게:** 후보나 검토 대상이 하나라도 있으면, 표시 대상이 아닌 박스를 원래의 약 30%로 흐리게 보여 준다. 저장 데이터나 history에 남지 않아야 하며, 표시를 끄거나 후보가 없어지면 원래대로 돌아온다.
- **핀:** 박스 오른쪽 위 모서리, 지름 12px, 흰 테두리 1.5px. Refine 검토는 노란 "!", reclass는 마젠타에 바꿀 클래스 번호(두 자리까지).
- **약한 변:** 박스 바깥에 떨어진 노란 삼각형. 화면에서 박스가 24px 미만이면 생략한다.
- **태그**(`→ 0 unfilled`, 면적 변화 `−42% area`): 화면의 박스 폭이 태그 폭 이상일 때, 또는 지금 N으로 이동한 박스나 선택된 박스일 때만 보인다.
- **면적 변화가 큰 박스의 빨간 표시**(`areaFlagged`)도 같은 체계로 바꾼다: 빨간 핀과 태그 [판단].
- 기존 "Show review marks on the canvas" 스위치가 핀, 화살표, 태그, 흐리게 처리를 모두 켜고 끈다.
- 숫자(12px, 30%, 24px)는 첫 값이다. 실제 화면에서 조정한다.

### 성능

- 목표: 박스 800개 판정(평균/비율)을 1초 안에 [판단]. 면적 감소는 Refine 실행 시간에 좌우된다.
- 판정 픽셀은 refine worker가 가진 이미지에서 계산한다. 박스마다 crop을 따로 IPC로 주고받지 않는다. 데스크톱(Tauri)에서는 refine이 네이티브(`native-refine-worker.ts`)라 이미지가 Rust 쪽에 있다. 처음에는 TS 판정을 다음 둘 중 하나로 붙인다: (a) 판정에 필요한 영역을 한 번에 가져오거나, (b) el-core에 작은 판정 함수를 추가하는 port(`port-module` 절차: golden fixture, parity, e2e 비교). 어느 쪽이 맞는지는 builder가 측정해서 정한다. 속도를 주장하려면 `docs/migration/BENCH.md` 측정 기록이 필요하다.

## 검증

- 단위: 판정 함수(평균, 비율, crop 경계, AND/OR, 켜진 판정 없음, 규칙 순서), settings 파서(옛 파일, 범위 자르기, 프리셋 호환).
- e2e(`tests/e2e/refine-edges.spec.ts`의 합성 SEM 데이터셋): 얼룩 박스 하나와, 불러온 크기보다 Refine 결과가 크게 줄어드는 박스 하나를 넣는다. Refine all을 적용한 뒤에도 면적 감소 후보가 유지되는지 확인한다. 그 박스만 후보가 되는지, Reclass selected 후 클래스가 바뀌고 한 번의 undo로 되돌아가는지, Lab 수치가 맞는지, 표시 스위치가 핀과 흐리게 처리를 끄는지 확인한다.
- 밀집 화면: 박스 700개 장면에서 라이트/다크 스크린샷을 찍어 핀과 태그가 겹치지 않는지 확인한다.
- 버전: 새 기능이므로 minor bump.

## Builder에게 맡기는 것

- 흐리게 처리를 구현하는 방법(fabric 객체 불투명도 vs overlay). 단, 저장과 history에 영향이 없어야 한다.
- 판정 픽셀을 가져오는 방식(위 성능 항목).
- Lab 편집기 안의 세부 배치.
