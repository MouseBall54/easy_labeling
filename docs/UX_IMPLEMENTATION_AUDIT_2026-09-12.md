# Easy Labeling 구현·UI 감사 보고서

작성일: 2026-09-12
범위: 현재 `main` 작업트리, 로컬 Vite 앱, 번들 샘플 작업공간

## 구현 현황 요약

Easy Labeling은 로컬 폴더를 데이터셋으로 사용하는 데스크톱 우선 이미지 라벨링 도구다. 주요 흐름은 다음과 같다.

1. 데이터셋을 열거나 번들 샘플을 불러온다.
2. Detection 또는 Segmentation 워크플로를 선택해 이미지와 주석을 편집한다.
3. Detection에서는 레이아웃, 템플릿 매칭, 배치 자동화 및 품질 검수를 사용한다.
4. 라벨 또는 마스크를 로컬 폴더에 저장한다.

확인한 주요 화면·기능은 초기 빈 작업공간, 샘플 로드, Detection 편집, Review 작업공간, Segmentation 작업공간, Automation 작업공간, Image Preprocessing 작업공간, 390px 반응형 화면이다.

확인 방법:

- 현재 로컬 앱을 1280×720 및 390×844 뷰포트에서 실행·관찰했다.
- 번들 샘플(17개 이미지)을 로드해 Detection, Segmentation, Review, Automation, Preprocessing 작업공간을 전환했다.
- 구현 코드와 E2E/단위 테스트를 대조했다.
- 단위 테스트는 56 파일, 342 테스트가 모두 통과했다.
- Chromium E2E는 21개 중 13개 통과, 8개 실패였다. 이 중 5개는 샘플 로드 후 첫 이미지가 `sample_1.jpg`가 아니라 라벨 없는 `sample (1).jpg`가 되는 동일 현상에 연관된다.

## 후속 작업 제안

### 빠르게 정리할 수 있는 작업

- 샘플 시작 이미지 및 E2E 기대값을 하나의 명시적 계약으로 정리한다.
- Automation 진입 시 선택된 레이아웃 미리보기를 즉시 동기화한다.
- Review 진입 시 첫 대기열 항목으로 이동하는 동작 또는 명시적 이동 CTA를 추가한다.
- Annotation 목록에 객체 번호·간단한 기하 정보·선택 강조를 추가한다.

### 기획 또는 사용자 결정이 먼저 필요한 작업

- 전처리를 독립 작업공간으로 유지할지, 자동화의 사전 설정 단계로 흡수할지 결정한다. 결정 전에는 두 패널을 동시에 노출하지 않는 편이 안전하다.
- 모바일을 공식적으로 지원할지, 데스크톱 전용 정책을 강화할지 결정한다. 현재 상태는 두 방향 모두 충족하지 못한다.
- Segmentation의 신규 이미지 기본 활성 클래스를 제품 규칙으로 정의한다.

### 실제 사용자 테스트나 데이터 확인이 필요한 작업

- 실제 라벨러에게 샘플 첫 화면에서 “다음 행동”을 묻고 빈 이미지와 라벨 이미지 중 어느 시작점이 이해하기 쉬운지 확인한다.
- Review 대기열에서 자동 이동과 현재 위치 안내 중 어느 방식이 작업 속도·통제감에 더 나은지 비교한다.
- 매칭 엔진 실패, 세그멘테이션 Undo, 워크플로 전환 E2E 실패를 깨끗한 테스트 환경에서 각각 단독 재현해 제품 결함과 테스트 결함을 구분한다.

## 당장 티켓으로 만들 만한 상위 5개 항목

1. **[P1] 번들 샘플의 기본 시작 이미지를 데모 목적에 맞게 고정하고 E2E 계약 복구**
2. **[P1] Review 진입 시 현재 이미지와 검수 대기열을 동기화**
3. **[P1] Image Preprocessing에서 무관한 Automation Inspector 제거 또는 전용 Inspector 제공**
4. **[P1] 최소 폭 이하에서 명시적 데스크톱 안내 또는 캔버스 우선 단일 패널 레이아웃 제공**
5. **[P2] 선택된 레이아웃의 Automation 미리보기 자동 표시**

## 한계

- 실제 사용자 데이터셋과 Electron 패키지 환경은 점검하지 않았다.
- 파괴적 작업(라벨 저장, 자동화 실행, 배치 실행)은 수행하지 않았다.
- 모바일 사용자 에이전트 자체의 차단 화면은 기존 E2E로만 확인했으며, 이번 실행은 데스크톱 사용자 에이전트의 좁은 뷰포트로 확인했다.
