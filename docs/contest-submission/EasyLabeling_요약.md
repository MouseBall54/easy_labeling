# EasyLabeling 요약

## 한 줄 소개

**EasyLabeling은 현장 이미지와 작업자의 판정 기준을 사람이 검수한 AI 학습 데이터로 전환하고, 이를 회사의 지속 가능한 데이터 자산으로 축적하도록 돕는 로컬 중심 자동화 라벨링 플랫폼이다.**

```text
현장 이미지
  → 객체·영역 라벨링
  → 자동화 초안 생성과 사람의 검수·보정
  → YOLO·Mask 학습 데이터 저장
  → 사내 AI 학습·평가에 활용할 데이터 자산 축적
```

## 개발 목적

현장 이미지 분석 업무에서는 반복 객체를 하나씩 표시하고, 경계를 정하고, 클래스를 맞추고, 결과를 다시 검수하는 작업에 많은 시간과 숙련도가 필요하다. 이 과정이 길어질수록 비전 AI 모델 학습에 필요한 데이터 준비가 늦어지고, 새로운 검사·분석 과제를 시작하기 위한 이미지 분석 셋업도 지연된다.

기존에는 일부 담당자가 코드 기반 자동화와 개별 도구를 활용해야 했던 작업을, 누구나 사용할 수 있는 GUI 프로그램으로 제공하는 것도 핵심 목적이다. 반복 구조는 Template Matching과 Layout으로 초안을 만들고, 작업자는 예외 사례와 경계를 검수·보정한다. Detection과 Segmentation 결과를 학습 형식으로 직접 저장함으로써, 이미지 확보부터 라벨 생성·검수·데이터셋 구성까지의 준비 흐름을 단축하는 것을 목표로 한다.

이러한 GUI 기반 작업 환경은 소수의 전문 인력에게 집중되던 데이터 구축 업무를 현업 부서로 쉽게 확산할 수 있는 기틀이 된다. 더 많은 구성원이 사내 이미지에 객체·영역·판정 기준이라는 의미를 부여하고, 필요할 때 다시 찾고 활용할 수 있어야 이미지 데이터가 단순 보관 자료를 넘어 분석과 의사결정을 위한 자산이 된다. 이를 통해 현장 담당자는 자신의 업무에서 더 빠르게 인사이트를 얻고, 조직은 데이터 활용 역량을 넓혀 경쟁력 확보에 기여할 수 있다.

장기적으로는 도서관처럼 방대한 이미지와 라벨 데이터를 목적, 데이터 형태, 클래스 체계, 품질 기준에 따라 분류·정리하는 데이터 기반을 구축하고자 한다. 이렇게 축적한 데이터는 개별 비전 AI 과제뿐 아니라 향후 대규모 AI 모델 개발과 고도화에 활용할 수 있는 중요한 기반이 된다.

궁극적으로는 현장 조건에 맞는 비전 AI 모델을 더 효과적으로 학습·평가하고, 이미지 분석 과제의 도입과 개선 속도를 높이는 데 목적이 있다. 학습된 모델의 분석 결과는 검사 정확도와 공정 의사결정을 지원해 제품 성능 및 수율 개선에 기여할 가능성이 있다. 다만 모델 성능 향상과 수율 개선은 라벨링 도구만으로 확정되는 결과가 아니므로, 대표 업무의 학습·평가 및 현장 적용 실증을 통해 별도로 검증해야 한다.

## AI 활용 내용

### AI 시대의 데이터 기반을 만드는 출발점

AI 과제의 성패는 모델을 도입하는 데서 끝나지 않는다. 현장의 설비, 제품, 검사 조건, 정상·예외 판단을 반영한 데이터를 지속적으로 만들고 검증할 수 있어야 모델을 업무에 맞게 학습·평가·개선할 수 있다. EasyLabeling은 바로 이 데이터 구축 단계의 진입장벽을 낮추는 도구다.

골드러시 시기에 금을 찾는 활동만큼 그 활동을 가능하게 한 곡괭이, 청바지와 같은 기반 도구가 중요했던 것처럼, AI 시대에도 모델 자체와 함께 데이터 생성·정제·품질관리 기반이 핵심 경쟁력이다. EasyLabeling은 외부 AI 서비스를 판매하거나 모델을 직접 학습하는 제품이 아니라, 회사가 필요한 AI를 효과적으로 구축할 수 있도록 현장의 이미지를 학습 가능한 정답 데이터로 바꾸는 기반을 제공한다.

### 활용 데이터와 현재 적용 기술

| 구분 | 내용 |
| --- | --- |
| 대상 데이터 | 제공된 반도체 단면, 회로기판, TEM 입자 이미지 등 현장 이미지 적용 시나리오 |
| Detection 데이터 | 이미지 속 반복 구조와 객체 위치를 Bounding Box로 정의하고 YOLO TXT 형식으로 저장 |
| Segmentation 데이터 | 입자·분석 대상의 경계를 Polygon, Brush, Erase 등으로 지정하고 PNG Semantic Mask 및 분할 형식으로 저장 |
| 템플릿 자동화 | OpenCV 기반 고정 크기 Template Matching으로 반복 구조 후보를 생성하고, Layout으로 검수한 박스 배치를 재사용 |
| 품질 점검 | 작은 박스, 경계 이탈, 중복, 필수 클래스 누락을 규칙 기반으로 점검하고 사람이 최종 보정 |

현재 자동화는 딥러닝 모델이 정답을 확정하는 방식이 아니다. 템플릿 매칭과 규칙 기반 점검으로 반복 작업의 초안을 만들고, 현업 사용자가 객체의 의미·예외 사례·경계 적합성을 검수해 확정한다. 이 구조는 자동화의 생산성과 현업 전문성을 함께 반영해 신뢰할 수 있는 학습 데이터를 만드는 데 목적이 있다.

### AI 과제 추진에서의 역할

EasyLabeling은 다음과 같은 데이터 개선 순환의 시작점으로 활용할 수 있다.

```text
현업 이미지와 판단 기준
  → EasyLabeling 라벨 생성·검수
  → 학습·평가용 데이터셋 구성
  → 사내 GPU 기반 모델 학습·평가
  → 오검출·미검출 원인 분석
  → 라벨 기준·예외 사례·추가 수집 데이터 보완
```

모델 평가에서 발견한 오류는 단순히 모델의 문제가 아니라 라벨 누락, 클래스 기준 불일치, 대표 사례 부족과 연결될 수 있다. EasyLabeling은 이러한 원인을 현업이 이미지 위에서 다시 확인하고 보정할 수 있게 해, 데이터와 모델을 함께 개선하는 기반을 마련한다.

### 공모전 시연 범위

- 반도체 단면 이미지에서 템플릿 매칭으로 후보 11개를 생성하고, 현업 판단에 맞지 않는 4개를 제거해 7개 YOLO Bounding Box를 저장했다.
- 검수한 7개 박스를 Layout으로 저장해 반복 구조가 있는 후속 이미지에서 재사용할 수 있음을 확인했다.
- 600 × 600 TEM 이미지에서 중앙 입자 5개 영역을 Polygon으로 지정하고 PNG Semantic Mask로 저장했다.

위 시연은 실제 GUI의 라벨 생성·검수·저장 흐름을 확인한 부분 적용 사례다. 후보 수, 매칭 점수, 저장 결과는 전체 이미지의 정답 개수나 일반적인 자동화 정확도를 의미하지 않으며, 실제 사업장 성과는 대표 업무를 대상으로 별도 실증해야 한다.

## 개선 전 개선 후와 경쟁력

### 적용 업무와 데이터 규모

주 적용 대상은 국소 영역을 경사 milling한 Top-view SEM 이미지이며, 해상도는 3,072 × 2,048픽셀이다. 반복 패턴이 많고 패턴별 클래스 분류, 인접 구조 분리, 경계 정확도를 일관되게 유지해야 한다. V-SPAS 단면 이미지와 TEM 이미지 분석에도 같은 데이터 구축 흐름을 적용할 수 있다.

월 평균 4개 과제에서 모델당 최소 200장의 학습 이미지를 사용하면 월 약 800장의 이미지가 필요하다. 이미지 한 장에는 약 20개 클래스와 400~600개 객체 라벨이 포함될 수 있으므로, 월 기준 약 32만~48만 개 객체 라벨을 다루는 업무 규모다. 현재까지 약 30개 데이터셋, 약 9,000장 이미지를 구축했으며, 누적 객체 라벨 규모는 약 360만~540만 개다. 이 값은 실제 업무 조건에 따른 산출 규모이며, 이미지당 객체 수와 과제 수에 따라 달라질 수 있다.

### 개선 전

| 업무 항목 | 기존 방식과 한계 |
| --- | --- |
| 라벨링 도구 | LabelImg와 Labelme를 사용했으나, 고해상도 반복 구조를 대량으로 라벨링하기에는 생산성이 낮았음 |
| 자동화 준비 | 담당자가 master Layout 로직을 Python·OpenCV 코드로 작성하고 JSON으로 저장한 뒤, 대상 이미지에서 Template Matching과 위치 정렬을 수행 |
| 신규 셋업 | 제품·구조·Layout이 바뀔 때마다 Layout을 다시 만들고 적용 코드와 파라미터를 수정·검증해야 했음 |
| 업무 확산 | 코드와 컴퓨터비전 역량이 필요해 1명의 담당자에게 작업이 집중되고, 변경 사항과 작업 기준을 다른 분석 담당자에게 공유·확산하기 어려웠음 |
| 품질·재작업 | 약 100장 작업 시 5~10장에서 위치 정렬 오류가 발생했고, 첫 Layout 셋업에서는 복잡한 클래스 번호 규칙 때문에 논리 오류가 빈번했음 |
| 보안 | 외부 반출이 허용되지 않는 사내 이미지이므로, 외부 클라우드 업로드 기반 라벨링 서비스의 사용이 불가했음 |

### 경쟁력

EasyLabeling의 경쟁력은 일반적인 수동 라벨링 도구와 달리, 반도체 이미지 분석 업무의 반복 구조와 보안 제약을 함께 고려했다는 점에 있다.

- **반도체 반복 패턴에 맞는 자동화**: 고정 배율의 SEM 셋업에서 Template Matching과 Layout을 결합해 반복 구조의 초안을 생성하고, 제품별 구조가 달라도 정해진 위치 안에서 균일하게 존재하는 패턴에 적용할 수 있다.
- **코드 자동화의 GUI 전환**: Python·OpenCV 기반 담당자 개인의 자동화 로직을 현업 분석 담당자가 사용할 수 있는 시각적 작업 환경으로 전환한다.
- **보안 제약을 고려한 로컬 중심 구조**: 민감한 사내 반도체 이미지를 외부 클라우드에 업로드하지 않고, 내부 환경에서 라벨링·검수·저장을 수행한다.
- **Detection과 Segmentation의 연계**: 반복 구조의 Bounding Box뿐 아니라 V-SPAS·TEM 분석에 필요한 영역 경계와 Mask 데이터를 같은 프로그램에서 구축할 수 있다.
- **사람 검수 기반의 품질 확보**: 자동화 결과를 정답으로 확정하지 않고, 인접 구조 분리·경계 정확도·클래스 일관성을 현업이 검수해 데이터 품질을 관리한다.
- **확장 가능한 데이터 자산화**: 제품과 과제가 늘어나도 Layout, Preset, 클래스 기준, 라벨 데이터를 재사용·정리해 향후 데이터셋 관리와 대규모 AI 모델 개발을 뒷받침할 수 있다.

| 기존 작업시간 | 동일 Layout의 200장 데이터셋 처리에 약 3시간 | 자동화 준비, 라벨링, 검수·보정, 저장을 포함한 기존 방식 기준 |
| 자동화 설정 | 동일 Layout의 200장 배치 기준 약 2분 | 제품·구조 변경 시에는 재설정 필요 |
| 검수·보정 | 자동화 후 동일 Layout의 200장 기준 약 10분 | 사람이 결과를 확인·보정하는 작업 기준. 저장 시간은 업무 영향이 크지 않음 |
| 작업시간 절감 | 200장 기준 약 3시간에서 약 12분으로 단축, 배치당 약 2시간 48분 절감(약 93.3%) | 동일 패턴·동일 Layout을 쓰는 200장 배치 기준. 신규 Layout 설계나 예외 사례가 많은 데이터셋에는 별도 측정 필요 |
| 현업 수행 인력 | 독립 수행 가능 인원 1명에서 5명으로 확대 | 5명 모두 라벨링, Template·Layout 설정, 데이터셋 저장 가능 |
| 재사용 자산 | Layout·Preset 재사용 사례 약 10건 | 반복 구조·유사 조건 업무에서 재활용한 사례 |
| 기존 오류 관리 대상 | 약 100장당 5~10장의 위치 정렬 오류와 첫 Layout 셋업의 클래스 규칙 논리 오류 | 기존 방식에서 확인된 재검수·재작업 요인. 적용 후 잔존 오류율은 별도 측정 필요 |
| 템플릿 매칭 배치 | 10장 배치 처리 986.83ms에서 610.64ms로 38.1% 개선 | 개발 환경의 진단 벤치마크 |
| 대량 Detection 처리 | 5,000개 박스 처리 453.9ms, 최종 렌더 요청 1회 | Fake Fabric 회귀 측정. 실제 GPU·브라우저 성능과 구분 |

## 정성적 효과

### 데이터 구축 역량을 0에서 100으로 전환

EasyLabeling 이전에는 개별 라벨링 도구와 담당자 개인의 Python·OpenCV 코드에 의존해 데이터셋을 구축했다. 자동화 로직, 클래스 규칙, Layout 설정과 결과 검수가 한 사람의 경험 안에 머물러 있어, 조직 차원의 표준 데이터 구축 체계는 사실상 부재했다. EasyLabeling은 이 단절된 업무를 현업이 직접 수행하는 하나의 표준 흐름으로 연결했다. 이는 단순히 라벨링 속도를 높인 개선이 아니라, 회사가 AI 학습 데이터를 효율적으로 구축·정제·축적할 수 있는 발판을 새로 마련한 성과다.

현장 이미지는 촬영·보관만으로는 공정 분석이나 AI 학습에 바로 쓰기 어렵다. 객체의 위치, 영역, 클래스와 예외 기준을 부여해야 비로소 이미지가 분석 가능한 데이터가 된다. EasyLabeling은 이미지에 현업의 의미와 판단 기준을 연결해, 수율·성능 이슈에 대응하기 위한 학습·평가 데이터와 공정 조건 분석의 출발점을 만든다. 이는 수율 또는 성능 향상을 도구 자체의 확정 성과로 주장하는 것이 아니라, 원인 분석·모델 검증·공정 조건 검토를 더 빠르게 시작할 수 있게 하는 데이터 기반의 성과다.

| 정성 성과 | 현업 관점의 변화 |
| --- | --- |
| 개인 의존 업무의 조직 역량화 | 1명의 코드·도메인 지식에 의존하던 작업을 5명의 엔지니어가 동일 GUI에서 독립 수행하는 체계로 전환했다. 담당자 변경·업무 확대 시에도 작업이 중단되지 않는 기반이다. |
| 암묵지의 표준화 | 클래스 정의, 경계 기준, 예외 사례, Template·Layout·Preset을 데이터와 함께 남겨 개인 경험에 머물던 판정 기준을 재사용 가능한 자산으로 전환했다. |
| 반복 입력에서 품질 검수로 역할 전환 | 작업자는 400~600개 객체를 일일이 입력하는 데서 벗어나 자동화 결과의 위치, 인접 구조, 클래스 적합성을 검수·보정하는 고부가가치 업무에 집중한다. |
| 효율적 데이터 구축의 발판 마련 | 이미지별 객체·영역·클래스에 현업의 의미를 부여하고, 자동화 설정과 검수 기준을 재사용함으로써 대량 이미지도 학습·평가 가능한 데이터로 지속 전환할 수 있는 기반을 만들었다. |
| 보안 제약 안의 AI 데이터 기반 확보 | 외부 반출이 절대 허용되지 않는 이미지도 로컬 또는 사내망 안에서 라벨링·검수·저장할 수 있어, 보안 때문에 멈춰 있던 AI 데이터 구축을 내부 환경에서 시작할 수 있게 됐다. |
| 데이터 품질의 선행 관리 | 모델 학습 이후에야 발견되던 라벨 누락, 클래스 기준 불일치, 경계 오류를 데이터 생성 단계에서 점검·보정하는 흐름을 만들었다. |
| 공정·성능 이슈의 분석 셋업 신속화 | 수율·성능 이슈가 발생했을 때 필요한 이미지의 객체, 영역, 정상·예외 기준을 빠르게 정의하고 학습·평가용 데이터셋을 구성할 수 있어, 소속 조직의 분석 셋업과 대응 시작을 앞당긴다. 실제 수율·성능 개선 효과는 대표 과제의 모델 평가와 현장 적용으로 별도 검증한다. |
| 지속 가능한 데이터 자산화 | 이미지, 라벨, 클래스 기준, Layout과 Preset을 함께 축적해 과제가 끝나도 사라지지 않는 학습·평가용 데이터 기반을 마련했다. |

## 협업 및 확산 성과

### 내부 협업 확대

EasyLabeling을 활용한 분석 업무가 1인 중심의 코드 기반 작업에서 누구나 사용할 수 있는 GUI 기반 업무로 전환되면서, 실제 활용 인력이 1명에서 5명으로 확대되었다. 각 엔지니어가 담당 제품과 분석 목적에 맞춰 직접 라벨링과 데이터셋 구축에 참여함으로써, 개인에게 집중되어 있던 AI 기술 적용 경험과 분석 노하우가 조직의 공동 역량으로 확산되었다.

구성원 간에 클래스 기준, Layout, Template, 검수 결과와 활용 방법을 공유하면서 다양한 제품과 이미지에 대한 분석 사례가 축적되고 있다. 이는 단순한 사용 인원 증가를 넘어, 여러 엔지니어가 AI 기술을 직접 경험하고 새로운 분석 관점과 인사이트를 함께 발굴하는 내부 협업 사례로 이어졌다.

### 외부 협업 및 분석 지원 확대

내부의 AI 활용 경험과 협업 분위기를 바탕으로 유관 조직에 대한 신규 분석 지원도 활발해지고 있다. Etch, Diff, Photo, CVD 기술팀을 비롯해 YE, PA1, PA2 등 다양한 조직의 분석 요청에 대응하며 적용 범위를 지속적으로 넓히고 있다.

특히 선단 기술을 개발하는 반도체연구소 TD1·TD2와 공정개발팀의 요청에도 확장 대응하고 있다. 반복적인 이미지 라벨링과 분석 준비 과정을 효율화함으로써 분석 착수와 데이터셋 구축을 앞당기고, 공정 문제에 대한 신속한 인사이트 확보와 공정 기술 수준 향상에 기여하고 있다.

| 협업 구분 | 확산 내용 | 주요 효과 |
| --- | --- | --- |
| 내부 협업 | 활용 인력 1명에서 5명으로 확대 | AI 기술 적용 경험과 분석 노하우를 개인 역량에서 조직 공동 역량으로 전환 |
| 기술 조직 협업 | Etch, Diff, Photo, CVD 기술팀 및 YE, PA1, PA2 분석 지원 | 제품·공정별 신규 분석 요청에 대한 대응 범위 확대 |
| 선단 개발 협업 | 반도체연구소 TD1·TD2 및 공정개발팀 요청 대응 | 선단 공정 분석의 착수 속도와 데이터 기반 의사결정 지원 |

> EasyLabeling은 특정 담당자의 기술을 대체하는 도구가 아니라, 한 사람의 전문성과 경험을 여러 구성원과 조직이 활용할 수 있도록 확장하는 협업 기반이다. 내부 5명으로의 활용 확대를 시작으로 다양한 기술·개발 조직의 분석 업무를 지원하며, 사내 이미지 데이터와 AI 활용 경험이 조직 공동의 경쟁력으로 이어지는 기틀을 마련하였다.

## 향후 확장 방향

현재 범위는 라벨링, 자동화, 리뷰, 저장이다. 향후에는 데이터셋 버전·품질 이력 관리, 사내 GPU 학습 요청, 모델 결과 비교, 오류 사례를 반영한 재라벨링과 재학습을 연결하는 방향으로 확장할 수 있다. 이를 위해 데이터 보관·접근 정책, GPU·저장소 자원, 담당 조직, 모델 평가 기준을 함께 마련해야 한다.
