# UX 개선 작업 지시 프롬프트

```text
Easy Labeling의 UX 개선 작업을 수행해줘.

먼저 다음 문서를 모두 읽고, 감사 근거·작업 순서·상태를 이해한 뒤 시작해줘.

- docs/UX_IMPLEMENTATION_AUDIT_2026-09-12.md
- docs/UX_IMPROVEMENT_WORK_PLAN_2026-09-12.md

목표:

- 감사 보고서의 P1/P2 UX 문제를 계획 문서 순서에 따라 해결한다.
- 기능을 추가하는 것이 목적이 아니라, 기존 기능의 흐름·상태·정보 구조가 어색하게 끊기는 문제를 최소 변경으로 해소한다.
- 각 작업의 진행 상태와 검증 결과를 `docs/UX_IMPROVEMENT_WORK_PLAN_2026-09-12.md`에 갱신한다.

작업 원칙:

1. 시작 전에 현재 Git 상태, 관련 코드, 테스트, 샘플 데이터 로드 흐름을 확인한다. 기존 사용자 변경은 보존한다.
2. 작업은 UX-01 → UX-02 → UX-03/UX-04 → UX-05/UX-06/UX-07 → QA-01 → 최종 검증 순서를 기본으로 한다.
3. D-01, D-02, D-03처럼 제품 결정을 요구하는 항목은 임의로 선택하지 않는다. 구현 전에 문서의 결정 기록을 확인하고, 결정이 없으면 해당 작업을 `Blocked`로 남긴 뒤 결정이 필요하다고 보고한다. 결정과 무관한 작업은 계속 진행한다.
4. UX-01의 기본안은 “샘플 로드 직후 라벨된 데모 이미지(`sample_1.jpg`, 52개 Detection 박스)를 보여준다”이다. 이 기본안을 뒤집을 만큼 명시적인 제품 결정이 없다면 이를 기준으로 구현·테스트를 정렬한다.
5. 구현 전후로 관련 E2E를 실행해 문제를 재현하고, 변경한 동작에 회귀 테스트를 추가하거나 기존 테스트를 정확한 사용자 계약으로 갱신한다.
6. 전체 리팩터링, 무관한 UI 정리, API 형식 변경, 삭제성 변경은 하지 않는다. 변경한 각 줄은 작업 ID와 연결돼야 한다.
7. 작업 중 위험한 자동화 실행·라벨 저장·배치 처리가 필요한 경우 번들 샘플만 사용하고, 실제 사용자 데이터는 변경하지 않는다.

각 작업의 완료 조건:

- UX-01: 샘플 시작 화면, 안내 문구, E2E의 초기 상태가 일치한다.
- UX-02: Review 진입 시 대기열과 현재 이미지의 관계가 명확하고, 이동 버튼 상태가 맞다.
- UX-03: 선택된 레이아웃은 다시 선택하지 않아도 미리보기 또는 명시적인 미리보기 CTA를 제공한다.
- UX-04: 동일 클래스의 주석을 화면 목록에서 구분하고 캔버스에서 확인할 수 있다.
- UX-05: 전처리 화면의 Inspector가 현재 전처리 목적과 일치한다.
- UX-06: 최소 폭 이하에서 캔버스가 양쪽 패널에 동시에 가려지지 않으며, 지원 정책이 명확하다.
- UX-07: Segmentation 첫 입력 전에 활성 클래스가 명확하고 Undo/Redo가 검증된다.
- QA-01: 현재 E2E 실패를 공통 원인과 독립 원인으로 분류하고, 결함 또는 테스트 수정으로 종결한다.

진척도 기록:

- 작업을 시작할 때 해당 작업을 `In progress`로 갱신한다.
- 완료하면 체크박스, 상태, 수정 파일, 실행한 명령과 PASS/FAIL 결과를 추가한다.
- 막히면 `Blocked`로 바꾸고 필요한 결정 ID와 질문을 남긴다.
- 완료되지 않은 항목을 `Done`이나 `Verified`로 표시하지 않는다.

최종 응답 형식:

1. 완료한 작업 ID와 핵심 변경 사항
2. 남은 Blocked 항목과 필요한 결정
3. 실행한 테스트와 결과
4. 계획 문서에서 갱신한 상태
5. 다음에 진행할 가장 작은 작업 단위
```
